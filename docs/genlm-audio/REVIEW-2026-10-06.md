# GenAID Audio review — 2026-10-06

Reviewer: Anton Timelarp. Scope is the in-repo VibeVoice podcast path (`genaid_audio/`, the gateway router, Ray Serve wiring, MCP tool registration, `serve.full.yaml`, and the two audio docs). Kokoro forks were read on GitHub and are not consumed by this repository. No pull requests were opened against them.

This document is the design and risk review. The accompanying draft PR only lands the low-risk controls called out as **fixed in PR**. Chunking, loudness, real MP3, auth, and autoscaling stay here on purpose.

## Design critique

### Request flow

```
Client
  -> Ray Serve ingress  :8002/genaid-audio   (serve.full.yaml -> genaid_audio.ray_core_builder)
  -> GenAIDAudioApp FastAPI                  (genaid_audio/serve_app.py)
  -> named detached actor GenAIDAudioModelActor
  -> genaid_audio/app.py  load_model / _generate_single / _generate_multi
  -> VibeVoiceForConditionalGenerationInference.generate

Script-only calls skip the actor:
  serve_app.generate_script -> app.generate_script -> AsyncOpenAI -> cluster vLLM

Gateway (second front door, not the only one):
  dlm_gateway/routers/genaid_audio.py
    health/info/voices: DeploymentHandle rpc_* when inside Ray, else HTTP
    /tts and /tts/multi-speaker: always HTTP to GENAID_AUDIO_BASE_URL
  dlmcp_app/tool_registry.py generate_speech / generate_script: HTTP to the same Serve route
```

`serve.full.yaml` binds `genaid_audio.ray_core_builder:build_genaid_audio` (around the `genaid-audio` application). `dlm_serve/serve_builders.py:build_genaid_audio` is a second entry point that reloads the same module. `archive/genaid_audio/deploy_genaid_audio.py` is a dead manual deployer: it still points vLLM at port 8000 and `GENAID_REMOTE_TTS_URL` at `10.1.8.69:7861`. Live code sets `remote_tts` to `None`. Do not revive that archive path.

The Serve class and the ASGI factory each construct a `GenAIDAudioRuntime` (`serve_app.py` `_build_fastapi_app` and `GenAIDAudioApp.__init__`). HTTP uses the factory instance. `rpc_*` uses the class instance. They share one named actor via `ray.get_actor` / `get_if_exists`, so this is wasted setup, not two models.

### What "chunking and stitching" actually is

There is no long-form splitter. `/podcast/generate` asks vLLM for a script, parses `Speaker N:` lines, and sends the entire script through one `model.generate` call.

- Single speaker: `max_new_tokens=4096` in `genaid_audio/app.py` (`_generate_single`).
- Multi-speaker and podcasts: `max_new_tokens=8192` in `_generate_multi`.
- The model itself concatenates acoustic chunks inside `genaid_audio/vibevoice/modular/modeling_vibevoice_inference.py` (`audio_chunks` then `torch.cat`). That is decoder streaming, not sentence segmentation, and nothing crossfades or restiches files.
- `vibevoice/modular/streamer.py` can queue those chunks. The HTTP API never attaches a streamer. The client waits for the full waveform.

Kokoro's pipeline (not wired here) does split on phoneme length 510 and on punctuation. VibeVoice does not.

A 30 minute request is still one GPU call. `ScriptGenerationRequest.duration_minutes` allows 0.5–30 (`app.py` field `le=30.0`). The script call caps `max_tokens` at 4096, so the LLM cannot actually emit 30 minutes, but whatever it emits is synthesized in one shot. Word-count duration uses 150 wpm (`target_words = duration_minutes * 150`), which is a script hint, not a measured audio duration.

### Speaker and voice mapping

`VoiceMapper._scan` walks `GENAID_VOICES_DIR` for `*.wav`. The preset key is the filename stem (`en-Alice_woman`). A short alias is the token before `_` after the language prefix (`Alice`). Later files overwrite earlier aliases. There is no stable id.

Podcast defaults (`app.py` `DEFAULT_VOICE_MAP`): Speaker 1 Alice, 2 Frank, 3 Maya, 4 Carter. Callers can override with `speaker_voices`. Single-speaker `voice_prompt_path` bypasses the catalog and is a cloning prompt.

The on-disk set documented in `docs/genlm-audio/VIBEVOICE_VOICE_PROFILES.md` is 9 wavs (Alice is 16 kHz; the others are 24 kHz). The gateway `BUILTIN_VOICES` list is 18 names (Nova, Lily, Emma, …) that the scanner will not find unless those files exist. When the backend is down, `/voices` returns that fictional catalog and the UI can offer voices TTS will reject.

`read_audio` mixes to mono and resamples to 24 kHz with librosa, or with `scipy.signal.resample` (linear) if librosa is missing. That is the whole sample-rate policy.

### Loudness and format

Input prompts can be normalized to about -25 dBFS by `AudioNormalizer` in `vibevoice_tokenizer_processor.py` when `db_normalize` is on. Output `save_audio` is called with `normalize=False` and always `soundfile.write`s PCM WAV at 24 kHz, including when the suffix is `.mp3` (`save_audio` around the `sf.write` calls). The HTTP layer still labels that body `audio/mpeg`. There is no LUFS target, no limiter, and no per-speaker gain match. One-shot generation hides the usual stitch click, and it also means a single bad segment cannot be regenerated.

### Latency and throughput

| Stage | Bound | Notes |
|---|---|---|
| Ingress replicas | min 1, max 2, 0 GPU, head-only | `serve_app.py` autoscaling block. CPU only. |
| Model actor | 1 named detached actor | `num_gpus` defaults to **0** (`DARBOTLM_GENAID_AUDIO_NUM_GPUS`). `serve.full.yaml` sets `'1'`. |
| Actor concurrency | Ray default 1 | Two ingress replicas queue on one actor. No batching. |
| Model load | up to 1800 s | `_MODEL_LOAD_TIMEOUT_S`. First TTS pays this inside the TTS timeout. |
| TTS actor wait | up to 1800 s | `_TTS_TIMEOUT_S`. |
| Gateway TTS | 60 s / 120 s | `dlm_gateway/routers/genaid_audio.py` `/tts` and `/tts/multi-speaker`. |
| MCP `generate_speech` | 120 s | `dlmcp_app/tool_registry.py`. |
| vLLM client | 120 s, hard cap 600 s | `guards.vllm_timeout_seconds`. Outer script wait is still 300 s and will not extend the HTTP client. |

Throughput is one utterance at a time per cluster, plus a full copy of the waveform in the actor, the Ray object store, and the HTTP body. No RTF metric is recorded. GPU memory is one resident model (good reuse) until `/model/unload` or a size switch, which deletes it and calls `empty_cache`. `device_map="cuda"` uses bf16; CPU fallback uses fp32 (`load_model`). A 7B fp32 load on a CPU box is a memory event, not a quality choice.

`/health` is liveness and stays 200 when the model is unloaded (`status` is `ready`). That is intentional. `/ready` is the new probe: the Serve process is ready while speech is `load_required`; the gateway `/ready` returns 503 when the backend cannot be contacted. Gateway `/health` still returns HTTP 200 with `"status": "unavailable"` so the portal can show that script generation remains local.

## Production risks

Severity is the production impact if the route is reachable. "Fixed in PR" means the draft PR changes that behavior. Residual items stay open.

### Critical

1. **Custom voice path was an arbitrary file read and a cloning prompt.** `voice_prompt_path` was passed to `soundfile` with no root check. Any wav the process could read could be cloned. **Fixed in PR.** `resolve_voice_file` (`genaid_audio/guards.py`) requires a real `.wav` inside `GENAID_VOICES_DIR` and rejects symlinks that escape it. The gateway rejects URLs, NUL, and `..` before the proxy. Preset names still resolve through `VoiceMapper`.

2. **`output_format` was interpolated into temp suffixes and podcast filenames.** A value such as `wav/../../...` could escape `OUTPUT_DIR` via `os.path.join` and `NamedTemporaryFile(suffix=...)`. **Fixed in PR.** Formats are `wav` or `mp3` only. Podcast bytes go through `write_bytes_exclusive`, which keeps the basename inside the output directory.

3. **`model_path` could point `from_pretrained` at any directory.** A directory under the caller's control can set `language_model_pretrained_name` and pull an unpinned Hub repo. **Path confinement is fixed** (`resolve_model_directory` must stay under `GENAID_MODEL_BASE`). **Hub fetch is not fixed by default.** `VibeVoiceProcessor.from_pretrained` still falls back to `Qwen/Qwen2.5-1.5B` with no revision (`vibevoice_processor.py` around the `cached_file` / `language_model_pretrained_name` lines). Set `GENAID_LOCAL_FILES_ONLY=1` after the tokenizer is staged. That switch is wired and off by default so existing first-boot downloads do not break.

4. **No authentication on the Serve route.** `serve_app.py` mounts CORS `allow_origins=["*"]` and does not check a caller. `serve.full.yaml` publishes `/genaid-audio` on the shared ingress, so clients can skip the gateway. Model load, unload, and cloning prompts are anonymous if that port is reachable. Not changed: an auth middleware here would break the portal without a shared scheme. Treat network policy as mandatory until a real gate exists.

### High

5. **Unbounded synthesis memory, only partly capped.** A multi-megabyte `text` or `script` previously reached `model.generate` with no limit. **Caps are fixed in PR** (`guards.py`): 8 000 characters per utterance, 4 000 per segment (env may raise to 8 000), 64 segments (ceiling 128), 20 000 characters total, 8 000 for prompts. Env vars can tighten, not raise the hard ceilings. **Not fixed:** those caps are still one GPU call. 20 000 characters plus `max_new_tokens=8192` can OOM a 1.5B resident. Duration remains `le=30`. Chunk-and-stitch is the real fix and is listed under P0 follow-ups.

6. **Timeouts do not cancel GPU work, and the gateway used to lie about why.** Serve waits up to 1800 s (`serve_app.py` `_TTS_TIMEOUT_S`). The gateway gives up at 60 s / 120 s and, previously, turned every failure into 503 "backend is not running", including 422s and timeouts. **Classification is fixed in PR** (`classify_upstream_failure`): connect errors 503, timeouts 504, upstream 4xx forwarded, other upstream HTTP 502. `ray.cancel(ref, force=False)` runs on actor timeout and does **not** stop a generate that has already started (`modeling_vibevoice_inference.generate` never checks a cancel flag). The actor stays busy. Not fixed: align the gateway budget with load+synthesize, or add a cooperative `stop_check_fn` (the generate signature already accepts one and the app never passes it).

7. **Model bytes are unpinned unless an operator opts in.** No revision, no hash, `snapshot_download` is not used on this path, but `from_pretrained` still talks to the Hub when local files are missing. **Fixed in PR as an opt-in pin:** if `SHA256SUMS` sits in the model dir, or `GENAID_MODEL_SHA256_FILE` points at one, load verifies every relative entry and rejects `..`. `GENAID_REQUIRE_MODEL_CHECKSUM=1` fails closed when the pin is absent. With neither set, load behavior is unchanged. Ship a pin before calling this solved.

8. **MP3 is mislabeled WAV.** `save_audio` only writes PCM via soundfile. Response `Content-Type` is `audio/mpeg` whenever the format is `mp3`. Players that trust the header fail; players that sniff may play it. Not changed, because rejecting `mp3` would break callers that already download the mislabeled file. See the P1 patch.

9. **Voice cloning has no consent gate.** VibeVoice is sample-conditioned cloning (`speech_tensors` / `voice_samples`). Built-in prompts are third-party recordings checked in under the voice library (see `VIBEVOICE_VOICE_PROFILES.md`). Custom prompts are now confined to that directory, which stops drive-by reads, and does **not** record consent, license, or a "this is a synthetic voice" marker. The response headers still echo up to 500 characters of the script (`X-Podcast-Script`).

### Medium

10. **Temp files leaked and broke on Windows.** `NamedTemporaryFile(..., delete=False)` left the handle open while soundfile wrote the same path (sharing violation on Windows) and skipped `unlink` on exception. **Fixed in PR.** `materialize_temp_audio` uses `mkstemp`, closes the fd, and unlinks in `finally`. Podcast writes run in `run_in_threadpool` / `asyncio.to_thread`.

11. **GPU reservation does not match the story in the wiki.** Wiki says lazy GPU. The actor requests `num_gpus` at **creation**, which is the first TTS or `/model/load`, and the code default is 0. On a box that forgets the yaml env, inference shares the GPU with whoever else landed there, or runs fp32 on CPU. Two ingress replicas do not give two GPUs. Unload `ray.kill`s the actor (`unload_model` in `serve_app.py`), which is the actual release. `_unload_locked` now moves the module to CPU when it can, `gc.collect()`s, and `empty_cache()`s. It does not return CUDA context memory to the OS reliably. Not a leak of "new model per request" — the singleton is reused under `model_lock`.

12. **Blocking inside async handlers.** `model.generate` on the FastAPI app path is in `run_in_threadpool`. On the actor it runs on the actor thread, which is correct for GPU. **Fixed in PR:** unload and podcast disk IO no longer run on the event loop. Residual: `import app` calls `os.makedirs(OUTPUT_DIR)` at import, and `VoiceMapper._scan` walks the tree during actor init. A huge or stuck mount delays startup. vLLM calls are async. `ray.get` is in `asyncio.to_thread`.

13. **User text in logs and headers.** Gateway `enhance-text` logged `request.text[:50]` and the model "improvements" line. **Fixed in PR** (length and provider only). Script and TTS 500s no longer return `str(exception)` to the client (that string often contains the prompt). Server logs still get `logger.exception`, which can include SDK messages. `X-Podcast-Script` still returns script text to every proxy. CR/LF are stripped so it is not header injection. Prefer a body field or an id.

14. **SSRF.** No request field is fetched as a URL. `voice_prompt_path` is a file and is now rejected when it looks like `http:` or `file:`. Residual SSRF is the Hub client inside `from_pretrained` (risk 3) and operator-configured `OPEN_WEBUI` / `GENAID_VLLM_URL`. The shared gateway `httpx` client uses `follow_redirects=True` (`dlm_gateway/config.py` `get_http_client`). A hostile or compromised audio backend could redirect the gateway. Not changed.

15. **Error hiding that remains.** Gateway `/health` is still HTTP 200 when the backend is down, by design for the portal. Serve `/health` is 200 when the model is not loaded. Use `/ready` on the gateway for "can I reach TTS?". Actor failures that are not `ValueError` / `FileNotFoundError` / `RequestLimitError` / `ValidationError` become 500 with the exception **type** only (`serve_app.py` `_ray_get`). The traceback stays in logs.

16. **Doc drift will cause a bad rollout.** `wiki/genaid-audio.md` shows `gpu_memory_used_mb`, `variant`, and voice objects the API does not return. `docs/genlm-audio/GENAID_AUDIO_INTEGRATION.md` still describes port 7861, a 227-line router, and `localhost` Gradio. `dlm_gateway/services.py` healthcheck for the catalog entry is `/health` on the Serve base URL, which is liveness, not model readiness.

### Low

17. **Alias collisions and catalog lies.** Short-name last-write-wins. Gateway offline catalog advertises voices that are not on disk.
18. **MD5 of the topic in the filename** (`hashlib.md5` in both podcast handlers). Not a security boundary. It does put a stable prefix of the topic into the output directory listing.
19. **Duplicate `_clean_script`** in `app.py` and the gateway router. They can drift.
20. **`importlib.reload`** in both builders. Reloading a module that already registered routes is surprising during a long-lived driver.

## Benchmark

**The 3D-cube spectrogram benchmark and its "3 serial auto-revisions" loop are not in this repository.** Searches for spectrogram, cube, and auto-revision under application code and docs did not find them. There is no audio eval harness here either: no frozen prompt set, no seed, no PESQ/STOI/mel distance/speaker-embedding score, no stopping rule, and nothing that would overfit because nothing is scored.

Nearest neighbors, so they are not mistaken for that loop:

- `scripts/benchmark_handle_vs_http.py` measures gateway RPC versus HTTP latency. It does not generate or score audio.
- `dlm_video/dlm_video_evaluation.py` is explicitly metadata-only ("does not decode media"). Gates are caller-supplied. `dlm_video/dlm_video_ray_runtime.py` records `benchmark_executed: False` on those gates. That is not an objective metric and not three automatic revisions.
- `GENAID_AUDIO_STACK_REV` in `serve.full.yaml` is a deploy label (`ray-core-lazy-20260612h`), not a benchmark iteration.

If that cube loop lives in another repo or on a dev box, it is not reproducible from this tree. Do not treat a self-graded revision counter as a quality gate. A real audio gate needs a frozen wav+transcript set, an external metric, a numeric stop (for example "stop after 3 runs or when mel distance delta < ε"), and a held-out set that the revision loop cannot see.

This repo does not import, pin, or vendor `kokoro`, `kokoro-onnx`, or `misaki`. `requirements.txt` has no such dependency. VibeVoice does not use espeak or ONNX. The notes below are for the forks only. Do not open PRs from this review.

Versions read from the default branches:

| Fork | Version | Python | Relevant pin |
|---|---|---|---|
| `dayour/kokoro` | 0.9.4 | `>=3.14,<3.15` | `misaki[en]==0.9.4+py314.1` via a path source `../misaki` |
| `dayour/misaki` | 0.9.4+py314.1 | `>=3.14,<3.15` | `espeakng-loader`, `phonemizer` in the `en` extra |
| `dayour/kokoro-onnx` | 0.6.1 | `>=3.14,<3.15` | `onnxruntime>=1.30`; GPU extra is `onnxruntime-gpu` on x86_64/AMD64 only |

Drift that matters if someone later wires them into DarbotLM: this service is not a 3.14-only environment. Kokoro's lock expects a sibling checkout of misaki, not the published extra. Installing "latest" Kokoro into the Ray image will not resolve.

### Model download (kokoro)

`kokoro/model.py` and `kokoro/pipeline.py` call `hf_hub_download` for `config.json`, `kokoro-v1_0.pth` / `kokoro-v1_1-zh.pth`, and `voices/{name}.pt` with **no revision and no checksum**. `torch.load(..., weights_only=True)` is already the right load flag. Suggested change, not applied:

```python
# kokoro/model.py — pin the Hub snapshot and check bytes before load
REVISION = os.environ.get("KOKORO_REVISION", "REPLACE_WITH_COMMIT")
PINS = {
    "config.json": "REPLACE_WITH_SHA256",
    "kokoro-v1_0.pth": "REPLACE_WITH_SHA256",
}

def _fetch(repo_id: str, filename: str) -> str:
    path = hf_hub_download(repo_id=repo_id, filename=filename, revision=REVISION)
    digest = hashlib.sha256(Path(path).read_bytes()).hexdigest()
    expected = PINS.get(filename)
    if expected and digest != expected:
        raise RuntimeError(f"checksum mismatch for {filename}")
    return path
```

Voice files need the same treatment (`voices/af_heart.pt` and the rest). Log the voice id and byte length, not `graphemes[:50]` (`pipeline.py` logs the text prefix today).

### ONNX providers (kokoro-onnx)

`src/kokoro_onnx/session.py` `resolve_providers` is better than a hard-coded CUDA string:

- `ONNX_PROVIDER` wins when that provider is actually installed.
- `onnxruntime-gpu` refuses to start if CUDA did not initialize (no silent CPU fallback).
- DirectML, OpenVINO, ROCm, and QNN are recognized by distribution name.

Gaps for EXHPQ:

- The DirectML branch returns every available provider and does **not** fail if the session fell back to CPU. Mirror the CUDA check.
- `onnxruntime` and `onnxruntime-directml` cannot both own the `onnxruntime` module. On Windows install `onnxruntime-directml` only, then `ONNX_PROVIDER=DmlExecutionProvider`.
- `onnxruntime-gpu` is marked unavailable on Linux ARM. A DGX Spark (aarch64) box will not get that extra; do not expect the GPU extra to solve Spark.

```python
# session.py, after InferenceSession(...)
if "DmlExecutionProvider" in providers and "DmlExecutionProvider" not in session.get_providers():
    raise RuntimeError(
        "DirectML did not initialize; refusing a silent CPU fallback. "
        "Install onnxruntime-directml (not both onnxruntime and onnxruntime-directml) "
        "or set ONNX_PROVIDER=CPUExecutionProvider."
    )
```

The caller passes a local `model_path`. Nothing in kokoro-onnx downloads the ONNX graph. Pin that file with SHA256 the same way as the PyTorch weights. There is no checksum helper today.

### espeak / misaki

`misaki/espeak.py` points phonemizer at `espeakng_loader.get_library_path()` and `get_data_path()`. That avoids a system `espeak-ng` package when the wheel's bundled library loads. It still needs a Windows wheel of `espeakng-loader` that contains `espeak-ng.dll`. If the import fails, Kokoro's English pipeline logs a warning and **skips out-of-dictionary words** instead of failing (`EspeakFallback` except path in `pipeline.py`). That hides a bad Windows install as "missing words" in the audio.

Suggested operational check, not a code change here:

```text
python -c "import espeakng_loader,phonemizer; from misaki.espeak import EspeakFallback; print(EspeakFallback(False)(type('T',(),{'text':'hello'})()))"
```

If that fails on EXHPQ, install the eSpeak NG Windows build and set `PHONEMIZER_ESPEAK_LIBRARY` to the dll. Do not apt-get espeak-ng on that box. VibeVoice on this repo does not need either binary.

def synthesize_turns(turns, voices, sr=24000):

## Rollout checklist — hpdayour and EXHPQ

hpdayour is treated as the Linux box that matches `serve.full.yaml` (`/mnt/fschia`, `/mnt/dlm-lib`). EXHPQ is the Windows box. VibeVoice on this repo does not call ffmpeg, espeak-ng, or ONNX. Those matter only if Kokoro is added later.

### Both

- [ ] Confirm `GENAID_MODEL_BASE/{1.5B,7B}` exists and is the directory Serve will load. A Hub id will not pass the new directory check.
- [ ] Generate `SHA256SUMS`, set `GENAID_REQUIRE_MODEL_CHECKSUM=1` and `GENAID_LOCAL_FILES_ONLY=1` only after a successful load with the pin in place.
- [ ] Voice wavs live in `GENAID_VOICES_DIR` and are real files, not symlinks to a home directory. Custom `voice_prompt_path` outside that directory now returns 400.
- [ ] Probe `GET /genaid-audio/health` (expect 200 even when the model is unloaded) and `GET /genaid-audio/ready`. On the gateway, `/genaid-audio/ready` is 503 until the Serve process answers.
- [ ] First TTS may exceed the gateway's 60 s and return 504 while the actor keeps loading. Do not retry in a tight loop; that queues more actor tasks.
- [ ] Send a short wav utterance and a 2-speaker script under the new caps. A payload over 8 000 characters (single) or 20 000 (script) is now 422.
